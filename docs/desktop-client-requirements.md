# 股票盯盘桌面端需求说明

## 1. 背景与目标

现有系统是 Node.js 网页应用。浏览器的画中画功能只能展示视频画面，无法提供完整交互，且 Safari 对 Canvas/MediaStream 画中画的支持存在兼容性限制。

新增一个独立、可安装的桌面客户端，支持 macOS 和 Windows。用户在客户端登录现有账号后，使用与网页端一致的数据和功能；其中“盯盘悬浮窗”必须是可交互的原生窗口，可固定显示在其他普通应用之上。

## 2. 仓库与系统边界

桌面端实施仓库为 `stock-desktop`，本地工作目录约定为：

```text
~/temp/stock-desktop
```

该目录由操作者从云端仓库拉取；后续桌面端代码、安装包配置与发布流水线均在此仓库维护。

| 系统 | 职责 |
| --- | --- |
| 当前 `stock` 仓库 | 网页端、Node.js 服务端、账号、股票数据、自选/分组/配置等 API |
| 新 `stock-desktop` 仓库 | macOS/Windows 客户端、桌面窗口、置顶盯盘、安装包、自动更新、网页唤起协议 |

桌面端不得复制账号、行情、自选股等后端业务逻辑；应通过 HTTPS 调用当前服务端 API，同一账号在网页与客户端间同步数据。

开始开发时，在 `~/temp/stock-desktop` 中阅读或复制本需求文档；新会话的实施指令为：

> 请读取桌面端需求文档，在 `~/temp/stock-desktop` 实现桌面客户端 MVP。

## 3. 技术选型

第一版使用 **Electron**。

原因：当前项目已有 Node.js 和原生 HTML/CSS/JavaScript 页面，Electron 能最大化复用前端能力，并提供 macOS/Windows 的原生窗口、系统托盘、协议唤起、安装打包和自动更新能力。

桌面端须启用安全默认值：

- `contextIsolation: true`；
- `nodeIntegration: false`；
- 仅通过 preload + `contextBridge` 暴露最小化原生能力；
- 所有 IPC 明确列出允许的通道和输入校验；
- 禁止任意外部页面获得 Electron/Node 权限；
- 不在日志、URL、协议参数中传递密码、会话 Cookie 或长期令牌。

## 4. 第一阶段（MVP）功能范围

### 4.1 主窗口

- 提供账号登录、登出和登录状态恢复。
- 登录后读取当前账号在服务端保存的自选分组、股票列表、基础配置。
- 展示自选盯盘列表和实时/定时行情刷新。
- 支持切换自选分组。
- 提供“打开/关闭盯盘悬浮窗”入口。
- 使用当前网页端已有的服务端 API，不改变现有网页用户的使用方式。

### 4.2 原生盯盘悬浮窗

创建与主窗口独立的原生窗口，而不是浏览器画中画或普通网页弹窗。

- 始终置顶于其他普通应用窗口之上；
- 可点击和操作，不能设置为鼠标穿透；
- 无边框或轻量标题栏，支持拖动；
- 支持窗口边缘缩放；
- 支持透明度调节；
- 支持设置窗口尺寸；
- 显示当前分组的股票代码、名称、最新价、涨跌额、涨跌幅和刷新状态；
- 支持切换分组、手动刷新、关闭悬浮窗；
- 记住用户的置顶状态、透明度、尺寸、位置和最近分组；
- 用户切换到其他应用后，悬浮窗仍可见；
- macOS 支持跨桌面空间显示，并尽可能显示在全屏应用之上；
- 不承诺覆盖锁屏、系统权限弹窗、系统安全界面等操作系统级窗口。

悬浮窗应使用 Electron `BrowserWindow` 的原生窗口能力：`setAlwaysOnTop(true)`。macOS 还应配置所有桌面空间可见，并启用全屏应用上方显示。窗口应保持可聚焦，以支持点击、选择和键盘操作。

### 4.3 数据同步

- 桌面端使用现有账号体系认证；浏览器与桌面端不共享 Cookie。
- 账号登录成功后由服务端签发桌面端可安全存储和刷新的会话/令牌机制；若现有 API 只支持 Cookie，会话方案需要在服务端扩展后再接入。
- 自选分组、股票、指标配置等以服务端账号数据为准。
- 本地只保存窗口偏好、缓存和安全存储的登录凭据；不得把密码明文写入文件。
- 离线或请求失败时应明确显示缓存/离线状态，并保留用户已输入但未提交的数据。

## 5. 网页唤起桌面端

桌面应用注册自定义协议，例如：

```text
stockwatch://watch?group=<group-id>
stockwatch://stock?symbol=sh600519
```

网页端新增“在桌面端打开”入口：

1. 用户点击后，网页尝试打开自定义协议；
2. 若应用已安装，系统启动或激活桌面端，并打开指定分组/股票；
3. 若未安装，网页展示下载入口或跳转下载页；
4. 不允许网页后台自动下载、安装或静默启动应用；
5. 协议参数只能传递公开的业务定位信息（如分组 ID、股票代码），不得传密码、Cookie、会话令牌或用户隐私数据。

## 6. 自动更新与发布

- 产出 macOS 安装包（Apple Silicon 和 Intel，按发布策略决定是否通用包）和 Windows 安装包；
- macOS 应用需要签名与公证，Windows 安装包应代码签名；
- 应用启动时和后台定时检查更新；
- 下载更新后提示用户“重启并更新”，不能在用户无感知时强制中断盯盘；
- 更新包和更新元数据通过 HTTPS 发布，并校验发布渠道；
- 为稳定版与测试版预留独立更新通道；
- 在 GitHub Actions 或等价 CI 中构建对应平台的安装包并发布版本。

## 7. 后续阶段

在 MVP 可用后，逐步将网页端已有功能迁入桌面端：

- 自选与分组的完整编辑能力；
- 指标配置、提醒、异动、全球市场；
- 账户配置、笔记、聊天、AI 研究等已有模块；
- 系统托盘、开机启动、全局快捷键；
- 多显示器窗口恢复和高 DPI 适配；
- 断线重连、后台刷新和更细粒度的通知策略。

## 8. 非目标

- 不继续把浏览器视频画中画当作桌面端置顶的主要方案；
- 不尝试绕过浏览器或操作系统的安装、权限、安全窗口限制；
- 不在桌面端重新实现股票数据抓取和账号数据库；
- 第一阶段不要求所有网页功能一次性重写完成。

## 9. MVP 验收标准

1. macOS 与 Windows 都能安装并启动客户端。
2. 用户可使用现有账号登录，且能看到与网页一致的自选分组和股票数据。
3. 点击“打开盯盘悬浮窗”后，窗口可操作、可拖动、可缩放、可调透明度。
4. 切换到 Safari、Edge、Office 等其他普通应用后，悬浮窗仍保持在前。
5. 关闭并重启客户端后，悬浮窗的大小、位置、透明度和最近分组能恢复。
6. 网页点击“在桌面端打开”可唤起已安装客户端并定位到对应分组或股票；未安装时提供下载引导。
7. 客户端检测到新版本后能下载并提示用户重启安装更新。
8. 登录凭据、密码、Cookie、长期令牌不出现在日志、自定义协议 URL 或明文配置文件中。
